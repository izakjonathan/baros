# Bar Ops v0.19.0-rc.2 — release candidate contract

## Status

**Candidate status: pending external build, staging, database and physical-device acceptance.**

This package is the first production release candidate. It freezes the accepted v0.18 interface and operational scope. It must not be described as production-ready until all external gates in `STAGING_ACCEPTANCE.md` and `DEPLOYMENT_SIGNOFF.md` pass against the exact tested deployment.

## No feature development

From rc.1 onward, do not add features, redesign pages, change data contracts or broaden scope. Only release-blocking defects may be corrected. Every correction must produce a new candidate (`rc.2`, `rc.3`, and so on) and rerun the complete quality and acceptance pipeline.

## Exact-source rule

- Build and deploy this exact source state.
- Record the commit SHA and Vercel deployment ID.
- Do not promote a rebuild from a different source state.
- Do not edit environment-sensitive files after validation.
- Preserve the accepted deployment for rollback evidence.

## Required promotion gates

1. Clean dependency installation on Node 24.
2. Verified lockfile generated by the successful clean install.
3. Full regression suite.
4. ESLint.
5. TypeScript validation.
6. Production environment validation.
7. Next.js production build.
8. Staging database verification and readiness endpoint.
9. Manager and employee workflow acceptance.
10. Browser, iPhone Safari, keyboard and VoiceOver acceptance.
11. No unresolved critical or high-severity defects.
12. Approval in `DEPLOYMENT_SIGNOFF.md`.

## External gates still pending

The current execution environment cannot resolve the scoped type packages from its configured npm proxy. Therefore clean install, lockfile verification, dependency-based lint/type/build gates, staging deployment, database verification and physical-device testing remain pending. They are intentionally not marked complete.
