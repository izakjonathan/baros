# Bar Ops Test Suite Structure

## Current release gates

`npm run test:current` is the authoritative source-level regression suite for the active release candidate. It covers current domain logic, security boundaries, tenant scoping, transaction contracts, accessibility contracts, the accepted Shift Plan visual invariants, authorization alignment, employee workspace ownership, and rc.5 type/build contracts.

`npm run test:all` is an alias for `test:current`.

## Historical release assertions

`npm run test:historical` preserves the full sequential chain of version-specific source assertions. These tests remain useful as release history and forensic evidence, but they are not authoritative current-interface acceptance gates. A historical assertion may describe a superseded design and must not block a current release solely because the accepted interface changed intentionally.

Historical tests must not be deleted merely to produce a passing result. When one is obsolete, record why the current contract supersedes it.

## Runtime gates

Source tests do not replace:

- ESLint;
- TypeScript;
- Next.js production build;
- API integration tests against PostgreSQL;
- browser workflow tests;
- responsive screenshots;
- iPhone Safari and VoiceOver acceptance.

## Lockfile status

The rc.5 workspace does not contain a fabricated lockfile. A package-lock must be generated by a successful clean resolution against the approved registry, then verified with `npm ci`. CI remains on `npm install` until that real lockfile exists; deterministic installation is therefore still a production blocker rather than a completed claim.
